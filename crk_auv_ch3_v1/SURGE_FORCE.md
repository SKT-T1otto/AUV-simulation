# 单艇已知纵向推力与 Gazebo 速度对照

Ubuntu 宿主机在已更新的源码目录执行 `bash tools/run_ch3_surge_force.sh`。默认无界面。程序在原有 crk-ros2-home 容器中按顺序启动两次独立的暂停世界，每次只生成一艘 auv_0，完成后回收进程。沿用现有模型、SDF 校验、互斥锁、接触监测和暂停步进。没有搜索任务、强化学习或位姿重置。

| 阶段 | 时长 | 艇体系纵向请求 |
|---|---:|---|
| 初始稳定 | 1.5 s | 0 N，进入驱动前检查三维速度 ≤0.02 m/s |
| 正向驱动 | 8.0 s | 第一个世界 5 N，第二个世界 10 N，均为整艇合力 |
| 撤推 | 7.0 s | 0 N，保留电机原有的滞后和变化率限制 |

纵向采用开环力输入。垂向保持项和姿态稳定力矩通过原八推进器分配器实现。记录每 20 ms 发布的各推进器牛顿指令，按本次 SDF 安装轴方向投影求和得到艇首合力，与控制器记录交叉校验。默认 Gazebo Thruster 的输入是牛顿指令；DDS 回执确认桥接器收到命令。这里的输入属于发布端记录，并非独立的艇壳测力。艇体系纵向速度来自 Gazebo 里程计。报告同时保留最大横向/垂向合成速度及横滚、俯仰，以判断一维近似的适用程度。[Gazebo Thruster 接口](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1Thruster.html)

### 理论曲线

在静水、近直航条件下，使用本次试验配置中的正值系数计算

```text
(m + m_ax) du/dt = Fx − d1 u − d2 |u| u
m = 13.5 kg, m_ax = 6.36 kg, d1 = 13.7 N·s/m, d2 = 141 N·s²/m²
```

仅在初始时刻使用实测纵向速度。每个物理区间按已发布合力零阶保持，用 RK4 连续向前积分，到实际里程计时间戳插值。没有随步用观测校正理论曲线，没有对现有数据拟合系数。两档理想稳定速度分别约为 0.146、0.222 m/s。实际末秒速度极差 ≤0.01 m/s 且末秒拟合斜率绝对值 ≤0.01 m/s² 时，报告标记观察到平台。撤推后从纵向发布合力持续落入 ±0.02 N 的第一控制区间起算；另以该段首个实测速率为基准，给出衰减到一半的时间。测量和理论的半速时间分别计算。全程另报速度 RMSE、最大绝对差、驱动后 0.2–0.6 s 平均加速度及横向运动。上述判据用于描述试验；误差不会因超过预期而被删除。

### 产物

终端输出 `BATCH_DIR`、`FIGURE` 和 `UPLOAD_FILE`。宿主机目录为 `/home/legion/AUV-simulation/results/ch3/surge_force_<唯一批次>/`。完整结果含两次试验的 SDF、配置、每步指令和前后状态、接触及进程日志、`surge_velocity.svg`、`surge_velocity.csv` 和 `surge_metrics.json`。有 Matplotlib 时另写 `surge_velocity.png`。相邻的同名 ZIP 校验 CRC 与逐文件 SHA-256 后可直接回传。异常停止返回非零并在部分 ZIP 中保留已有证据。

### 历史前向包线回放

已有 Linux/Gazebo x 轴运动记录也能绘图。以原始完整试验目录和独立输出目录为参数，从 `crk_auv_ch3_v1` 执行

```bash
python -B -m crk_ch3.surge_report --archive-x /path/to/envelope_x_run --out /path/to/new_report
```

历史回放使用 auv_0 的八路闭环指令。其“零加速度请求”段含阻力补偿，主动制动也有纵向输入，应与两档开环撤推结果分别引用。两种图都核对同参数模型的动力学实现，实艇误差需要独立的实艇输入和速度数据。
