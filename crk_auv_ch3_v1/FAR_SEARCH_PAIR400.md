# G6 远目标步零候选入围的完整任务对照 v1

在已更新到发布提交的 Ubuntu 宿主机执行一次。

```bash
cd /home/legion/AUV-simulation/source && bash tools/run_ch3_far_search_pair400.sh
```

使用既有 crk-ros2-home、/opt/crk-g5-cpu-v1 及宿主机绑定挂载。默认 headless。启动器检查源码清单、Git 工作树、宿主机输出及容器挂载。运行 A、核对停止及进程组回收，随后以另一独立 Gazebo 分区和新世界运行 B。每组有独立的暂停时钟基准。每组墙钟看门狗为 120 分钟，任务时限为 400 个 0.2 s 步。Ctrl-C 请求取消，等待返回并保留部分证据。

## 实验与终止

原远目标场景 g6_search_engineering，场景种子 1，规划种子 2729，四艇 D2＋ZERO。

- A `initial_original400` 执行原 D2 的步零候选生成、评分及安装。
- B `initial_quadrant400` 在唯一一次步零 INITIALIZE 中复用 [已登记的四象限候选规则](INITIAL_CANDIDATES_PAIR.md)。执行艇使用同一原生待命池及联合评分，随后所有规划都走原 D2。
- 两个运行沿用相同的运动、地图、探测、交接和捕获逻辑。首次发现后继续执行。原生 timeout、obstacle_collision 和 success 单独列出。物理接触、时钟、停止或回收失败属于工程失败。完成的 N 步须有 N 条 transition、10N 条控制记录、可核对的原生终止与停止证据。无发现的正常超时可以进入下一组和生成正式比较报告。

## 运行前登记的分析口径

1. 逐组核对实际公共输入、12 个候选、原分配、执行艇、原规范哈希及分数。离散选择与浮点差异分别记录，沿用绝对分数容差 1e−10。四艇初始位置、速度和姿态差限为 0.002 m、0.01 m/s 和 1°。每艘搜索艇共同跟踪期间的位置、速度、姿态差限为 0.01 m、0.02 m/s 和 1°，请求及调节后加速度差限均为 0.05 m/s²。以步前实际 guidance 和每一子步的控制与里程计回核。参考上次第 14 步开始的指令分叉和第 20 步末三艇有向差 +0.4564、+0.5615、+0.4678 m，输出本次值和差值。历史值不参与规划或物理验收。
2. 搜索者为 auv_0、auv_1、auv_2。每次完成步进后，将四艇同时间戳的原始里程计转换到任务坐标，z 向上。两次运行按相对各自暂停 epoch 的同一实际时间戳配对。主窗口从 0 到两组较早的发现步末、较早终止步末或 80 s，包含触发事件的该步运动。另报逐组自身完整搜索阶段。未对齐的采样槽显式记录，相关区间不跨缺口积分，标记对照不充分。实际采样可在请求边界前最多 2 ms，报告有效积分时长和未观测秒数。
3. 主指标为三对搜索艇水平间距的算术平均 Dxy 的时间均值，分别计算 A、B，再取 B−A。积分采用相邻同步采样的梯形法。另存每对艇的水平及三维间距、最小艇间距、三维均距，以及 auv_2 高度和同刻 B−A 高度差。正值表示该单对运行的 B 均值较大。入围规则对发现概率的影响需另外的重复实验。
4. 右半区从 x=10 m 起算，包括边界。首入按首个进入的实测样本记时。相邻实测点间作线性连接，对跨中线的区间分摊时长。累计艇秒除以三艇可用积分时长。原生 20×20 m 水平区域有 10×10 格；内部界线归较大坐标侧，外边界归末格。按实测端点及相邻点连线穿过的格去重，恰好穿过对角交点时不额外计两个侧格。报告各艇、并集及至少两艇经过的格数。原生扫描计数含重置扫描，最终占据图未知比例取自终止地图快照。这两项与轨迹经过的水平格各有独立字段。
5. 首次发现取原生 target_found 首次转真、found_step 与 finder_id，时间精度为 0.2 s。复核原生 detector 步事件中的三艇起末点与同一步移动目标起末点，沿用原生线段相对最近距离、各角色运行时有效探测半径和距离相等时的艇号顺序。原生跳过探测的碰撞步单独处理。真值只在运行后供核验。两组均发现才计算时间差；未发现保留空值并给出观察截止。收到交接、首次可据此决策、连续保持与原生成功分别记录。

## 单包交付

结果在 /home/legion/AUV-simulation/results/ch3/g6_far_search_pair400_<批次ID>.zip。可选环境变量 CRK_EXPORT_DIR 指向已挂载的共享目录。启动器复核成员、CRC、逐文件 SHA-256，复制到共享目录后再核对整包哈希。终端最后打印 BATCH_STATUS、UPLOAD_FILE 和 ZIP_SHA256。发送 UPLOAD_FILE 对应的一个文件即可。

ZIP 保存每组原始记录、初始化、场景、配置、Git SHA、批次日志和 SHA256SUMS。REPORT.md 给出结论；comparison.json 给出共同及逐组窗口、原生结局和证据缺项；timeseries.csv、agent_metrics.json 与四份 SVG 分别保留轨迹、间距、高度及有符号高度差。两组正常超时属于 completed。若启动、步进、回收或可比性核验失败，返回非零并保留已有原始文件和失败报告。
