# G6 远目标初始候选的 32 步成对验证

在 Ubuntu 宿主机运行以下一条命令。已有的 crk-ros2-home 容器和 /opt/crk-g5-cpu-v1 提供 ROS、Gazebo 和原生任务依赖。

```bash
cd /home/legion/AUV-simulation/source && git pull --ff-only origin main && bash tools/run_ch3_initial_candidates_pair.sh
```

默认无界面。启动器检查源码清单与容器挂载，先跑 A，读回 A 的初始化、控制记录、时钟、停止及进程回收证据，通过后才为 B 启动新世界。两组使用同一原始远目标场景、场景种子和 planner_seed 2729。每组正式 max_steps 为 400，外部最多 32 步，每步 0.2 s。到预算记为 diagnostic_budget_completed。提前原生终止保留原生结果。接触、时钟异常、中断和其他工程失败保留已有数据，批次返回非零。

## 唯一实验变量

- initial_original32 按原 D2 初始化、评分并安装分配。只读观察器抄录实际送入评分器的候选。
- initial_quadrant32 在同一个首次 INITIALIZE 中，对每个搜索艇独立在原安全公共有序池取四个候选。按左下、左上、右下、右上的象限次序，每区按原排名取首个通过原资格、三维间距、路径可达和物理旅行时间预算的格点。x 或 y 恰为 10 时归右或上。艇内按格点去重，空缺按全池原顺序补足。候选从本次公共状态计算。两组使用相同的待命候选、旅行服务、联合评分、安装流程和原提交时机，执行艇最终待命点允许随联合解变化。
- 初始化作用域退出即恢复原搜索池方法。每步保存实际方法名、当步的原生规划提议、已安装分配、tracker、运动前制导和运动后的制导。ZERO 表示四艇归一化残差动作均为零。原控制器持续接收导航加速度并施加推力。

**初始化核对。** 对照公开图、安全图、完整初始公共状态、规范分配哈希、12 个搜索候选的原排名与顺序、所选路线、四个待命候选和联合解。A 的三处终点依次为 (1,3,5.5)、(1,1,5.5)、(1,1,5.5)，B 为 (11,11,0.5)、(11,11,0.5)、(11,1,0.5)。候选旅行量和搜索／联合分数用原值比对，绝对容差 1e−10。离散及公共输入匹配、浮点差和未经取整的规范哈希分别记录。运行前的这些参考值只供验收使用。

## 预登记的运动判据

|艇|共同首跟踪点|A 下一点|B 下一点|
|---|---|---|---|
|auv_0|(1,1,1.5)|(1,3,2.5)|(3,3,1.5)|
|auv_1|(1,5,2.5)|(1,3,3.5)|(3,7,1.5)|
|auv_2|(1,9,3.5)|(1,9,4.5)|(1,9,2.5)|

1. 对齐每次暂停后的任务 epoch。初态四艇 A/B 的位置、世界速度、四元数姿态角差分别不超过 0.002 m、0.01 m/s、1°。逐艇到首次不同**运动前**跟踪点之前，最大差限为 0.01 m、0.02 m/s、1°。请求与调节后加速度向量差分别不超过 0.05 m/s²。共同阶段允许高层初始路线和执行艇待命点按实验条件不同。
2. 控制命令以 20 ms 子步起点计时。艇位取四艇屏障的实测时间戳，允许相对请求时钟滞后至多 2 ms。A/B 只比较相对 epoch 时间戳完全相同的样本。按艇记录首次数值差（向量差大于 1e−9 m/s²）及首次可分辨差（大于 0.05 m/s²）。运动边界依据实际导航目标、艇位、速度、原生先验增益、角色限制和 ZERO 残差重算请求，回核十个子步实际送给控制器的数值。
3. 分叉方向为表中 B 下一点减 A 下一点的三维单位向量。每个样本保存 B−A 的 xyz 差、三维距离、有向投影及有符号垂直位移。两组均到各自登记的分叉跟踪点、请求及调节后加速度分叉后，有向投影连续三个同步样本超过 max(0.01 m, 共同阶段投影差绝对峰值)，判为观察到预期方向的位移。另记请求后首次越过阈值的三维分离。auv_2 的预期方向为负 z。
4. 每艇截至两组中较早的初始路线替换步末，最多 32 步。步末换路只影响下一步运动。同一几何路径内 tracker 推进、候选 ID 重标均保留在同一段。每艇同时报告共同窗口及本组初始路线至首次替换的进展。沿当前指令腿做有界投影，按同一跟踪索引连续期间取首末差，回退抵消前进，阈值切换的余段不给进度。余程从实测终点到仍施加的旧跟踪点再接旧路径后缀。窗内没有换路时，换路余程留空。
5. 结果逐艇区分只改变了分配、请求已分叉且位移未分辨、已观察到预期方向的位移、对照不充分。共同阶段超过容差或无法配对物理时刻则保留数据并报告对照不充分。位移未分辨属于有效结果。发现目标、进入右半区和 400 步任务成败均不作为本实验验收指标。

## 交付

终端最后三行给出 BATCH_STATUS、UPLOAD_FILE 和 ZIP_SHA256。只需发送 UPLOAD_FILE 对应的一个 ZIP。若当前 shell 已通过 CRK_EXPORT_DIR 指向已挂载的 Windows 共享目录，将同时获得经 SHA-256 复核的同一文件。中断时程序通过共享取消标记通知容器，等待暂停、子进程回收和部分结果打包。

ZIP 含两次运行各自的原始记录、容器标准输出、批次日志、Git SHA、REPORT.md、comparison.json、agent_metrics.json、projection.svg 和逐文件 SHA256SUMS。比较输入由本批次直接指定。结果保存在 /home/legion/AUV-simulation/results/ch3/。每次使用唯一批次号，宿主机发布时校验 ZIP 的 CRC、全部成员及各文件 SHA-256。

Windows 有界反馈带与替身测试用于核对软件链。物理分叉结论以 Linux 包中的同步实测记录为准。

若旧结果目录由 root 创建，启动器为本次新目录设置宿主机用户所有权。仅在当前用户连结果父目录也无法穿越时，为该用户补充父目录的遍历权限。
